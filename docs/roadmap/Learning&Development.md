## Plan: Continuous Learning, Memory & Deep Integration

**TL;DR:** Implement three interconnected systems: (1) a **Feedback Loop Agent** that learns from user edits/approvals, (2) a **Long-Term Memory Layer** that persists insights across interactions, and (3) expand **Integration Hub** for seamless CRM/calendar/enrichment connections.

---

### 1. "Always Learning" — Feedback Loop System

**What exists:** RAG retrieves context but doesn't learn from outcomes.

**What to build:**

| Step                               | Description                                                                                                                                                 |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1.1 User Edit Tracking**         | When a user edits a generated email before sending, capture the `before` and `after` text in a `feedback_events` table.                                     |
| **1.2 Approval/Rejection Signals** | Track which drafts get sent vs discarded; store outcome alongside draft ID.                                                                                 |
| **1.3 Feedback Analyzer Agent**    | New Tier-3 agent that periodically analyzes feedback events, extracts patterns (e.g., "user always removes 'Best regards'"), stores as `style_preferences`. |
| **1.4 Prompt Injection**           | Copywriter pulls `style_preferences` for the tenant/user and injects them into the system prompt.                                                           |

**Files to create/modify:**

- New: `tiers/tier_3/feedback_agent/`
- New: Supabase table `feedback_events` (draft_id, before_text, after_text, outcome, tenant_id)
- Modify: copywriter.py — inject learned preferences

---

### 2. "Customised to You" — Long-Term Memory Layer

**What exists:** Conversation history + lead context, but no relationship memory or cross-conversation insights.

**What to build:**

| Step                              | Description                                                                                                          |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **2.1 Relationship Memory Table** | New table: `relationship_memory` (lead_id, tenant_id, key_facts, sentiment_history, engagement_score, last_updated). |
| **2.2 Memory Writer Hook**        | After each conversation, extract key facts (via LLM summarization) and upsert into `relationship_memory`.            |
| **2.3 Vector Memory Index**       | Embed `key_facts` into vector store for semantic retrieval ("What did we discuss about pricing?").                   |
| **2.4 Profile Writer Agent**      | New agent that synthesizes lead data + relationship memory + enrichment into a comprehensive profile.                |
| **2.5 Memory Retrieval in RAG**   | Enhance `get_lead_context` to include relationship memory and vector search of past interactions.                    |

**Files to create/modify:**

- New: `tiers/tier_3/memory_agent/` — writes/summarizes relationship memory
- New: `tiers/tier_3/profile_writer_agent/` — generates rich profiles
- Modify: services/vectordb/client.py — implement real vector search (currently placeholder)
- Modify: tiers/tier_3/rag_agent/tools/reply_context.py — include memory retrieval

---

### 3. "Deeply Integrated" — Integration Hub Expansion

**What exists:** Email (Gmail), basic enrichment (CrunchBase, LinkedIn), webhook patterns.

**What to build:**

### Database Schema Additions

```sql
-- Feedback/Learning
CREATE TABLE feedback_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES clients(id),
  user_id UUID,
  draft_id UUID,
  before_text TEXT,
  after_text TEXT,
  outcome TEXT, -- 'sent', 'discarded', 'edited'
  diff_summary JSONB,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Long-term Memory
CREATE TABLE relationship_memory (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES clients(id),
  lead_id UUID REFERENCES leads(id),
  key_facts JSONB DEFAULT '[]',
  sentiment_trend TEXT, -- 'positive', 'neutral', 'declining'
  engagement_score FLOAT DEFAULT 0,
  total_interactions INT DEFAULT 0,
  last_interaction_at TIMESTAMPTZ,
  embedding VECTOR(1536),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- Tenant Credentials (encrypted)
CREATE TABLE tenant_credentials (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES clients(id),
  provider TEXT NOT NULL, -- 'hubspot', 'salesforce', 'google_calendar'
  credentials_encrypted BYTEA,
  scopes TEXT[],
  expires_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

### Part 2: Autonomous Use Cases

#### 2.1 Track Your Market

- **Market Monitor Agent**: Watch Crunchbase, LinkedIn, job boards for buying signals
- **ICP Discovery Engine**: Analyze closed-won deals to identify new prospect patterns
- **Signal Webhook Ingestion**: Receive funding, hiring, tech stack change signals
- **Tables**: `market_signals`, `icp_profiles`

#### 2.2 Engage Key Accounts (ABM)

- **Account Hierarchy**: Company → Contacts with persona roles
- **Multithreading Engine**: Engage 3+ decision-makers per account simultaneously
- **Persona Messaging**: Different value props for Economic Buyer vs Champion vs Technical Evaluator
- **Tables**: `accounts`, `account_contacts`

#### 2.3 Generate Demand

- **Content Library**: Case studies, webinars, whitepapers matched to persona/industry
- **Event Campaigns**: Invite → Reminder → Post-event follow-up sequences
- **Tables**: `content_library`, `content_engagement`

#### 2.4 Activate High-Intent Leads

- **Website Visitor Tracking**: Clearbit Reveal / 6sense integration
- **Job Change Detection**: LinkedIn alerts for role changes
- **Intent Scoring**: Combine signals into priority score
- **Auto-Activation Rules**: Score > threshold → add to priority campaign
- **Tables**: `intent_signals`, `activation_rules`

#### 2.5 Revive Leads

- **Stale Lead Detector**: Identify leads with no activity in 30/60/90 days
- **Context-Aware Revival**: Reference past conversations, what's changed
- **Win-Back Sequences**: Dormant, lost deal, churned customer templates
- **Tables**: `lead_lifecycle`, `revival_campaigns`

#### 2.6 Reach New Markets

- **Language Detection**: Auto-detect from email domain, name, company location
- **Multi-Language Copywriter**: GPT-4 with 100+ language support
- **Timezone-Aware Scheduling**: Send at optimal local time
- **Regional Compliance**: GDPR, CASL, LGPD rules
- **New columns**: `leads.preferred_language`, `leads.timezone`, `leads.region`
